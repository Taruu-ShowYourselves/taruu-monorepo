**The two structural gotchas, both verified 2026-08-03:**

1. `summarizeVote` (originally L2340) is the file's **only** non-exported top-level helper. It is
   used only by `getMunicipalityProfile`. It moves into `db/municipality.ts` and stays unexported.
2. `getActiveUserPushTokens` (originally L1168) `await`s `getPushTokensByUserId`. Both are in
   `db/push.ts`, so the call resolves locally. It is the file's **only** intra-file call between
   exports. Re-check before finishing:
   `grep -nE "await (get|count|has|is|upsert|record)[A-Za-z]+\(" apps/web/src/lib/supabase/db/*.ts`
   — any hit crossing a module boundary needs an explicit import, and must never import from
   `./index`, which would create a cycle.

`getVotesNeedingResolution` and `updateVoteResolutionStatus` read and write `votes`, not
`vote_nfts`, but they are the resolution pipeline that triggers minting and they sit inside the NFT
banner. They stay in `db/nfts.ts`. Note it in the module header so a reader is not surprised to find
`votes` there.

**The barrel and why no importer changes.** Node and TypeScript resolve `@/lib/supabase/db` to
`db/index.ts` once `db.ts` is gone. Deleting `db.ts` and creating `db/index.ts` in the same task is
therefore invisible to all 62 importers — but only if both happen together. Doing them in separate
tasks leaves the tree broken in between.

`apps/web/vitest.config.ts` maps `@` to `./src`; `apps/web/tsconfig.json` carries the matching
`paths`. Neither needs a change. If either does, stop — something about the split is wrong.
