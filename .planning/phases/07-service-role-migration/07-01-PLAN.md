Create `supabase/migrations/20260803000001_webhook_events_rls_hotfix.sql`.

It does exactly one thing: replace `"Service role full access to webhook_events"` with the same
policy scoped `TO service_role`.

```sql
DROP POLICY IF EXISTS "Service role full access to webhook_events" ON webhook_events;

CREATE POLICY "Service role full access to webhook_events"
  ON webhook_events FOR ALL
  TO service_role
  USING (true)
  WITH CHECK (true);
```

The header comment must state, in prose: that the original policy omitted the `TO` clause and so
defaulted to `PUBLIC`; that `NEXT_PUBLIC_SUPABASE_ANON_KEY` is published by definition, so any
caller could read `payload_hash`/`idempotency_key`, `DELETE` rows to re-enable webhook replay, or
`INSERT` a row for a future `event_id` to make a legitimate webhook look already-processed; and
that this is separated from `20260803000002_rls_policy_audit.sql` so it can be applied on its own
without waiting for the rest of the phase.

Idempotent: `DROP POLICY IF EXISTS` first, so re-applying is safe.
