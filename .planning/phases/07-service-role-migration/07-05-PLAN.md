The house style for a corrective migration, `20260628000002_fix_rls_user_id_helper.sql`:

```sql
DROP POLICY IF EXISTS "Users can see their own treasury transactions" ON treasury_transactions;
CREATE POLICY "Users can see their own treasury transactions"
  ON treasury_transactions
  FOR SELECT
  USING (user_id = public.user_id());
```

Two non-negotiable rules:

1. **`public.user_id()`, never `auth.uid()`.** `auth.uid()` returns NULL under this project's custom
   JWT and silently matches zero rows. This has already been a corrective migration once
   (`20260628000002`) and repeating it is the phase's most likely self-inflicted wound.
2. **`SECURITY DEFINER` for any policy that reads a role or grant table.** Phase 5 established the
   pattern (`public.is_platform_admin()`, `public.can_admin_space(text)`, both
   `STABLE SECURITY DEFINER SET search_path = public`). A policy that queries the table it protects
   raises `42P17`, infinite recursion.

FINDING-2 verbatim, `supabase/migrations/20250118000001_vote_nfts.sql:169-172`:

```sql
CREATE POLICY "Vote NFTs are publicly readable"
  ON vote_nfts
  FOR SELECT
  USING (true);
```

`vote_nfts` columns (`20250118000001:~60-100`) include `user_id UUID REFERENCES users(id)`,
`wallet_address TEXT`, `vote_id UUID`, `mint_address`, `metadata_uri`, `status`, `metadata JSONB`.
The `USING (true)` policy therefore publishes the join from a Taruu user id to a specific vote and a
Solana wallet — the product's secret ballot, readable with the published anon key. Plan 07-01
decided how the public gallery keeps working (projection view vs privileged aggregate); implement
that decision, do not re-open it.

Postgres notes that matter here:
- Multiple `FOR SELECT` policies on one table are **OR**-ed. Adding an own-row policy next to a
  `USING (true)` policy widens nothing; the public one must be dropped for the own-row one to mean
  anything.
- A policy with no `TO` clause applies `TO PUBLIC` — the cause of FINDING-1. Write `TO` explicitly
  on every policy in this file.
- `merch_orders` has RLS enabled with zero policies: deliberate deny-all
  (`20260622000001_merch_orders_rls.sql`). Do not "fix" it into having policies unless the
  classification asked for one.
- `CREATE POLICY` has no `IF NOT EXISTS`. Idempotence means `DROP POLICY IF EXISTS` before every
  `CREATE POLICY`, including for policies this file creates for the first time.
