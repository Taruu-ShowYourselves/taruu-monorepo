<objective>
Make the deploy path a decided path. Today `deploy.yml` spends two minutes building and then dies
inside wrangler on an unset `CLOUDFLARE_API_TOKEN`, and even a successful deploy would be marked
red by a notification step that 403s. Meanwhile the only way the live site has ever been deployed
is a human running `pnpm deploy` by hand, and nothing in the repo says so.

Purpose: go-live must not depend on a pipeline nobody trusts. This plan makes the failure fast and
legible, stops a cosmetic notification from failing a real deploy, adds a names-only production
readiness check so "are the secrets set?" is a command rather than a memory, and corrects the
runbook — which still tells the reader participation costs ₪3.

Output: a guarded workflow, `apps/web/scripts/preflight-prod.sh`, and a corrected
`apps/web/docs/INTEGRATIONS.md`. No secret VALUE is read, printed, or copied anywhere in this plan.
</objective>

    **What it does.** Answers "is production ready?" using only information that is safe to print.

    1. Read the set of secret NAMES currently on the Worker:
       `"$WRANGLER" secret list` → JSON array of `{name, type}`. Parse names with `node -e` reading
       stdin (node is guaranteed present in this repo; `jq` is not). If the command fails — not
       logged in, no network, wrangler missing — print a clear message and exit `2` (distinct from
       `1` = not ready), rather than silently reporting everything missing.
    2. Compare against three hardcoded name lists — `BLOCKER`, `PAID`, `DEGRADES` — exactly as
       enumerated in this plan's `<interfaces>` block.
    3. Print a three-section report. Every line is `TIER  NAME  set|MISSING`. **Only names and the
       two words `set` / `MISSING` are ever printed.** Never a value, never a length, never a prefix,
       never a hash.
    4. Read `GREENINVOICE_ENV` out of `wrangler.jsonc` as text (`grep`/`sed`, no JSON parser — the
       file is JSONC with comments and will not parse as JSON) and print it. If it is `production`,
       print a warning line naming gate G3: `WARNING: GREENINVOICE_ENV=production — confirm
       GI-LEGAL-CHECKLIST.md and GI-PRIME-CHECKLIST.md are signed off (gate G3) before serving paid
       traffic.`
    5. Exit codes, documented in the header comment and enforced:
       - `0` — every `BLOCKER` and every `PAID` name is set
       - `1` — one or more `BLOCKER` or `PAID` names missing (`DEGRADES` misses print a `note:` line and do **not** change the exit code)
       - `2` — could not query the Worker at all

    **Flags.**
    - `--names-only` — print just the three name lists and exit `0` without contacting Cloudflare.
      This is what CI and the plan's own verify command use, so the check is runnable with no
      credentials at all.
    - `--help` — usage and the exit-code table; exit `0`.

    **Header comment.** State in the first 12 lines: this script prints secret NAMES and set/unset
    state only; it never reads, prints, or copies a secret VALUE; `wrangler secret list` and
    `sync-secrets.sh --dry-run` are the only sanctioned inspection commands; and to set a secret use
    `wrangler secret put <NAME>` interactively or `./scripts/sync-secrets.sh`.

    **Forbidden, and the script must contain none of them:** `wrangler secret get`, `cat .dev.vars`,
    `echo "$SECRET"`, or any expansion that could emit a value. The only `.dev.vars` interaction
    permitted is delegating to `sync-secrets.sh --dry-run`, which prints names.
  </action>
