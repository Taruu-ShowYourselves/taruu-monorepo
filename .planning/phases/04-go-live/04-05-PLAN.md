`pnpm deploy` builds **and** deploys in one step. Do **not** run `next build` while `next dev` is
running — it clobbers `.next` (project memory, `taruu-dev-verify`).

**Routes served** (`wrangler.jsonc:37-41`), all `custom_domain: true`:
`taruu.co.il`, `www.taruu.co.il`, `api.taruu.co.il`.

**Live logs:** `cd apps/web && node_modules/.bin/wrangler tail --format pretty`.
`observability.enabled` is `true` (`wrangler.jsonc:31-33`), so the dashboard's Logs view also works.

**The `validateEnv()` situation** — this is a check, not a fix. Today:
- `apps/web/src/lib/env.ts:146` `validateEnv()` has **zero callers** anywhere in `apps/web/src`.
- Its schemas require six variables with **zero** runtime readers: `AUTH0_CLIENT_ID`,
  `AUTH0_CLIENT_SECRET`, `NEXT_PUBLIC_AUTH0_DOMAIN`, `NEXT_PUBLIC_AUTH0_CLIENT_ID`, `SUPABASE_URL`,
  `SUPABASE_SERVICE_KEY`.
- The two variables actually read most — `SUPABASE_SERVICE_ROLE_KEY` (5 readers) and
  `NEXT_PUBLIC_SUPABASE_URL` (7) — are absent from the *server* schema.

Phase 3 SEC-05 fixes this. Determine the state at deploy time by grepping for a call site
(`grep -rn "validateEnv()" apps/web/src | grep -v "lib/env.ts"`) and record which of two worlds you
are in:
- **SEC-05 landed** → a call site exists; the Worker boots and the logs show no env error → criterion 1
  is met, evidenced.
- **SEC-05 not landed** → no call site; nothing validates at startup → record criterion 1 as
  **NOT MET** with that reason. **Do not wire `validateEnv()` up in this plan** — it would fail closed
  on the orphaned `AUTH0_*` variables and take production down, which is precisely why SEC-05 is a
  separate, planned piece of work.

**Cron reality** (`wrangler.jsonc:58-68`): the schedules API rejected the full cron list behind an
account-level gate; only `0 */6 * * *` (the knesset day-order sync) is live. The other three routes
in `worker.ts`'s `CRON_ROUTES` — verification notifications, vote resolution, NFT minting — have **no
trigger**. Note this in the evidence: vote resolution not running is a product-visible gap at launch,
not a cosmetic one.

**Redaction rule for the evidence file.** Record deployment ids, URLs, HTTP statuses, route names,
and log lines with secrets stripped. Never record: an API token, a service-role key, a JWT, a session
cookie, a resident's real email or name, or any card detail.
