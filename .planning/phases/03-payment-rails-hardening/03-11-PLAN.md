raises is the mechanism; a code comment is not. Phase 5's `role_grant_events`
(`supabase/migrations/20260802000002_role_grants_and_applications.sql`) landed an append-only audit table in
this repository already — **read it first and follow its trigger and policy pattern** rather than inventing
a second idiom.

by product design — `01-02-SUMMARY.md` records that the existing `USING (true)` public-read policies on
treasury were left deliberately — but confirm that decision still holds with the COIN-01 answer in hand
before copying it.

**Amounts are integers in the smallest unit.** `payments.amount` and `treasury_transactions` are in agorot.
Do not introduce a float column for money. If the ledger must hold both a fiat and a chain-side amount, hold
two integer columns with explicit units in their names, not one ambiguous numeric.

**What COIN-01's answer changes about this plan** (Task 1's gate exists for these):
- who the legal owner of the pool is → whether the ledger is scoped per municipality, per vote, or per trust
- whether funds must be segregated → whether one ledger can hold several municipalities' money at all

returning a typed `ReconciliationReport`:

```typescript
export type MismatchKind = 'missing_on_chain' | 'missing_in_ledger' | 'amount_mismatch';

export interface ReconciliationMismatch {
  readonly kind: MismatchKind;
  readonly municipalityId: string;
  readonly signature: string | null;
  readonly ledgerAmount: number | null;   // smallest unit, integer
  readonly chainAmount: number | null;    // smallest unit, integer
}

export interface ReconciliationReport {
  readonly checked: number;
  readonly matched: number;
  readonly openMismatches: number;
  readonly mismatches: readonly ReconciliationMismatch[];
}
```

Rules that make this trustworthy rather than decorative:
- Pure. The chain reader is injected by the caller and its results are passed in, so the comparison can be
  unit tested with fixtures and re-run over historical data.
- Match on the chain signature, never on amount alone — two identical deposits are not interchangeable.
- An entry whose signature is `null` (a fiat movement that never went on chain) is **excluded from the chain
  comparison and counted separately**, not silently matched. Say so in the docstring.
- Never mutate an entry to "fix" a mismatch. The report is the output; a correction is a compensating entry
  written by `appendCivicPoolEntry`.
- Integer arithmetic only. No floats anywhere in the comparison.
