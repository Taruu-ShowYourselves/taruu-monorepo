Make the server the authority on what a swap costs, so COIN-03's requirement — *"every quote the UI shows is the quote that executes"* — is enforced rather than assumed. Localise every failure into Hebrew.

**THIS PLAN IS BLOCKED.** Task 1 is a hard gate. Do not execute Tasks 2 or 3 until COIN-01's written Israeli legal sign-off is on file. Purpose: `apps/web/src/app/api/bags/swap/route.ts:35-52` accepts a **client-supplied `quote` object** and validates only that `inputAmount`, `outputAmount` and `fee` are present, then passes it straight to `bagsService.executeSwap`. Nothing ties that object to a quote the server ever issued, to this user, or to any point in time. The quote the UI showed and the quote that executes are related only by the client's good manners.

Output: server-issued, signed, short-lived quote tokens; a swap route that will not execute anything else; Hebrew errors throughout.

**COIN-03, verbatim** (`REQUIREMENTS.md:50`):
> Buy/sell runs through the existing Bags surfaces with server-side validation; no raw chain error reaches
> the user, and every quote the UI shows is the quote that executes.

The hole, `apps/web/src/app/api/bags/swap/route.ts:33-52`:
```typescript
const body = await request.json();
const { quote, walletAddress } = body;
if (!quote) return 400;
if (!quote.inputAmount || !quote.outputAmount || !quote.fee) {
  return NextResponse.json({ error: 'Invalid quote structure' }, { status: 400 });
}
// …then straight to bagsService.executeSwap({ quote, userWallet })
```
The route's own docstring already concedes the problem: *"This endpoint should only be called with a valid
quote that was obtained recently (quotes expire)"* — a comment where a check belongs.

The issuing side, `apps/web/src/app/api/bags/quote/route.ts:18-45` — session-gated, validates
`inputMint`/`outputMint`/`amount`, calls `bagsService.getQuote`, and returns the quote **unsigned**.

The service (`apps/web/src/services/bags/index.ts`):
```typescript
export async function getQuote(params: QuoteParams): Promise<Quote>          // :194
export async function executeSwap(params: SwapParams): Promise<SwapResult>   // :215
export class BagsServiceError extends Error                                  // :84
```

**The signing primitive already exists.** Phase 5's RLS transport landed `apps/web/src/lib/supabase/user-token.ts`,
which mints a short-lived HS256 token with `jose` over a Worker secret. **Read it and follow its idiom** —
the same `jose` import, the same short-TTL discipline, the same guard-at-point-of-use for a missing secret.
Do not add a second JWT library and do not hand-roll HMAC-over-JSON.

Which secret signs a quote is a decision to make and record. `JWT_SECRET` already signs the session cookie
and `SUPABASE_JWT_SECRET` signs the PostgREST token; a quote is a third purpose. Prefer a distinct
`BAGS_QUOTE_SECRET`, guarded at point of use and added to `env.ts`'s optional set (plan 03-01 rewrote that
schema — read it as it stands). If a new secret is not acceptable, reuse `JWT_SECRET` **with a distinct
`aud`/`purpose` claim** so a session cookie can never be replayed as a quote, and say so in the SUMMARY.

Error localisation precedent: `apps/web/src/services/participation/submitParticipation.ts` (plan 02.1-05)
maps every server outcome to a Hebrew message and never surfaces a raw string. Both bags routes currently
return English (`'Invalid quote structure'`, `'Bags.fm integration is not configured'`, and
`BagsServiceError` messages) straight to the client.

Test precedents: `apps/web/src/__tests__/api/bags-swap.test.ts` and `bags-trending.test.ts` already exist —
**read them; the swap suite will need rewriting in place** rather than duplicating.

**Part A — `apps/web/src/services/bags/quoteAuthority.ts`.** Sign the quote so the server can recognise its
own. Mirror `lib/supabase/user-token.ts`'s `jose` usage.

```typescript
/** Quotes are stale fast. Short enough that a price cannot drift far; long enough for a user to confirm. */
export const QUOTE_TTL_SECONDS = 60;

export interface QuoteClaims {
  readonly userId: string;
  readonly inputMint: string;
  readonly outputMint: string;
  readonly inputAmount: string;
  readonly outputAmount: string;
  readonly slippageBps: number;
}

export async function issueQuoteToken(claims: QuoteClaims): Promise<string>;

export type QuoteVerification =
  | { readonly ok: true; readonly claims: QuoteClaims }
  | { readonly ok: false; readonly reason: 'expired' | 'invalid' | 'wrong_user' };

export async function verifyQuoteToken(token: string, userId: string): Promise<QuoteVerification>;
```

Sign the **economic terms** — both mints, both amounts, the slippage — not a nonce pointing at server state.
The token then *is* the quote, and a swap cannot execute terms the server never quoted. Guard a missing
signing secret at point of use, exactly as `user-token.ts` does, and fail closed rather than issuing an
unsigned token. Record which secret you used and why, per the `<interfaces>` note.

**Part B — `POST /api/bags/quote`.** After `bagsService.getQuote` succeeds, call `issueQuoteToken` with the
session user id and the quote's terms, and return `{ quote, quoteToken }`. Leave the existing session gate,
the `isConfigured` guard and the input validation in place, but localise their error bodies to Hebrew.

**Part C — `POST /api/bags/swap`.** Replace the client-supplied `quote` with `quoteToken`:
- read `{ quoteToken, walletAddress }`; **do not read `quote` at all**, so a client that still sends one is
  ignored rather than trusted;
- `verifyQuoteToken(quoteToken, session.userId)`; on `expired` return 409 with a Hebrew message telling the
  user the price refreshed and to try again; on `invalid` or `wrong_user` return 400 with a generic Hebrew
  message that reveals nothing about which check failed;
- rebuild the `SwapParams` **from the verified claims**, never from the request body;
- wrap `bagsService.executeSwap` so a `BagsServiceError` is logged server-side and answered with a Hebrew
  message — no provider or chain string in the response;
- keep the session gate, the `isConfigured` 503, and the existing wallet-resolution fallback.

If Task 1 returned `cleared-with-conditions`, **stop** — a holdings cap or a residency restriction is a
server-side check that belongs in a re-planned task, not improvised here.

No `any`. Never log a token or a secret.
