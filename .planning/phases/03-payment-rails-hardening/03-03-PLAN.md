<objective>
Retire the participation payment rail from every client of the payments API: the shared Zod contracts, the api-client, and the mobile checkout screen.

Purpose: plan 03-02 makes the server reject `vote_participation`. If the contracts and clients still offer it, the monorepo keeps advertising a product Taruu does not sell, and a mobile user can still be routed to a checkout screen for a free action. Two of these were already broken and nobody noticed: `paymentsApi.createVotePayment` posts `{ type: 'vote' }` and `createVoteCreationPayment` posts `{ type: 'create_vote' }` — **neither string has ever been accepted** by `/api/payments/create`, which validates against `['vote_participation','vote_creation']`. They also read `response.paymentIntent`, a key the route has never returned. This plan fixes the one that should exist and deletes the one that should not.

Output: creation-only contracts, a working api-client method, a creation-only mobile checkout.
</objective>
