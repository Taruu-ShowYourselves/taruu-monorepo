<objective>
Retire the ₪3 `vote_participation` payment rail from the web app, and stop crediting the civic pool on a vote-creation fee. After this plan the product can create exactly one kind of payment: a ₪50 vote creation, 100% platform.

Purpose: participation became free in `cfa5d25`, but `/api/payments/create` still accepts `type: 'vote_participation'`, still quotes ₪3, and `GET /api/payments/create` still **publishes** that price to anyone who asks. Phase 02.1 deliberately deferred this — `services/payments/greenInvoice.ts:39` says in the source, "Retiring this rail belongs to the Phase 3 payment re-scope." This is that phase. Separately, the webhook deposits the **full** ₪50 creation fee into the municipality treasury ledger (`webhook/route.ts:128-138`), which directly contradicts PAY-06's "100% platform; the civic pool is not credited on creation".

Output: a single-purpose payment service, a creation-only API contract, a webhook with no participation branch and no creation-fee treasury credit, and a rewritten test suite that locks the new contract in.
</objective>
