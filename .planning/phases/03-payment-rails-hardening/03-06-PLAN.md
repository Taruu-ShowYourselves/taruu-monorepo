<objective>
Make the vote-creation funnel incapable of claiming a vote that does not exist. Delete the fabricated seal, and make the return page honour Green Invoice's failure redirect instead of reassuring a user whose card was declined.

Purpose: `votes/create/page.tsx:196-203` is a "graceful MOCK fallback" that, when the API returns 200 without a checkout URL, sets `sealHash` to `Math.random().toString(16)` and renders the full success surface — headline `הצבעה נוצרה · CREATED`, a `Receipt` reading `דמי יצירה ₪50`, and a `SealCard` with `status="sealed"`. **`POST /api/votes` is never called on that branch.** This is the identical defect Phase 02.1 removed from the participation funnel (`mockHash()`), still alive in the creation funnel. Separately, `greenInvoice.ts:163` registers a `failureUrl` carrying `&status=failed` that `payments/return/page.tsx` never reads, so a declined payment shows *"התשלום עדיין נחתם. ההצבעה תפורסם תוך רגעים."*

Output: a pure, tested checkout module; a create page whose only success path is a real Green Invoice redirect; a return page that tells the truth about a failed payment.
</objective>
