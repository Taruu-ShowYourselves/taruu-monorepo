# Phase 02.1 Plan 05: Client Participation - Server-Confirmed Write and Honest Receipt Summary

**`ParticipationFlow.tsx` now posts to `POST /api/votes/[id]/participate` via a pure `submitParticipation` module and only shows a receipt once the server confirms the ballot - `mockHash()`, `SealCard`, and every `חתום בבלוקצ׳יין` / `נחתם` claim are gone from the casting funnel.**

## Accomplishments
- `submitParticipation(voteId, optionId, fetchImpl)` is a pure, fetch-injectable async function that POSTs `{ optionId }` to `/api/votes/[id]/participate` and returns a discriminated `ParticipationSubmission` - `{ status: 'recorded', ballot, alreadyRecorded }` or `{ status: 'rejected', code, message }` - mapping every server outcome (200 recorded, 200 already-recorded, malformed 200, 401, 403 by code, 429, 400, 404, 500, any other status, and a thrown/offline fetch) to one of eight Hebrew `PARTICIPATION_MESSAGES`. No branch ever surfaces a raw server error string.
- `ParticipationFlow.tsx`'s `sealVote()` (client-side `mockHash()`, a fabricated block number, and a fake `ts: new Date()...`) is gone entirely. `recordVote()` calls `submitParticipation`, and the flow only reaches `stage: 'receipt'` on `status === 'recorded'`; a rejection sets a Hebrew `errorNote` under the gate notice, keeps the user on `stage: 'confirm'`, and never touches `onComplete`.
- The receipt stage - previously unreachable, because `sealVote` called `onComplete()` synchronously and flipped `hasVoted` before the receipt could render - now shows only server-backed facts: the chosen option, cost `חינם`, status `נרשם`, the server's `ballot.id` under `מספר רישום`, and a `recordedAt` timestamp derived from `new Date(ballot.createdAt)` (never a client clock). `onComplete(ballot.optionId)` fires only when the resident clicks the receipt's own `צפו בתוצאות` CTA.
- `SealCard`, the `✓ חתום בבלוקצ׳יין · בלתי ניתן לשינוי` trust line, and step 3's `חתימה` label/kicker are removed with no replacement, per the phase's LOCKED decision. Step 3 is now labelled `רישום` and the receipt heading reads `הקול שלכם נרשם.`
- A duplicate submit (double-click, retry, or a resident who already voted) is a success: the receipt renders with `alreadyRecorded: true` and copy that reads "כבר הצבעתם בהצבעה הזו. זה הרישום הקיים שלכם" against the same, real ballot row - not a bare error.
- The vote page's context bullet, post-vote `votedMessage`, and results footer, plus `VotesList`'s per-ballot trust note, no longer claim a blockchain seal; they now state what the server actually guarantees (verified identity + residency, counted once, one vote per resident).
- `onComplete`'s new `(optionId: string) => void` signature is wired at the page level to set `selectedOption` before `hasVoted`, so the results panel's `isMine` highlight works correctly for a vote just cast in this session (previously it only worked after a page reload, via `userVote` from the GET response).
- Two new test files: `submit-participation.test.ts` (15 tests, full network-contract coverage via an injected `vi.fn()` - never touches global `fetch`) and `participation-receipt-honesty.test.ts` (26 source-assertion tests across all four touched files, guarding against `mockHash`, `SealCard`, and any chain-seal copy regressing, and proving the flow reaches the server before showing a receipt).
- Full web suite: 62 files / 755 tests green (was 60/714 after plan 04; +2 files, +41 tests). `pnpm --filter @sync/web typecheck` clean. `pnpm --filter @sync/web lint`: 0 errors, 2 pre-existing unrelated warnings (`postcss.config.mjs`, `worker.ts`).
