# Phase 02.1 Plan 03: Retire the ₪3 Participation Legacy Summary

**Removed `VOTE_COST = 3` from `@sync/shared` in favour of an explicit `VOTE_PARTICIPATION_COST = 0`, rewrote the mobile vote screen's cost/blockchain copy, pinned the still-wired legacy Green Invoice ₪3 rail to a local literal, and added a source-assertion regression test — all without touching `CREATE_VOTE_COST` or the live vote-creation payment path.**

## Accomplishments
- `VOTE_COST` no longer exists anywhere in the monorepo — not as an export, not as a comment reference — replaced by an explicit, documented `VOTE_PARTICIPATION_COST = 0`
- Mobile vote screen (`apps/mobile/app/vote/[id].tsx`) no longer quotes a ₪3 fee or claims a blockchain recording; it now states participation is free and requires one-time identity/residency verification
- The legacy `vote_participation` Green Invoice rail (still wired through `/api/payments/create` though unused by any web UI) kept its exact ₪3 behaviour, now pinned to a local literal and labelled as legacy, deferred to the Phase 3 payment re-scope
- `CREATE_VOTE_COST = 50` and every vote-creation consumer (`votes/create/page.tsx`, `PricingContent.tsx`, mobile `(tabs)/create.tsx`) verified untouched by grep
- New guard test (`participation-cost-legacy.test.ts`, 10 assertions) fails the suite if `VOTE_COST` reappears, if the mobile ₪3/blockchain copy returns, or if the pinned legacy GI amount drifts

## Decisions Made
- No `VOTE_COST` deprecated alias — every consumer updated directly, so there is no dangling name for a future accidental re-import to find
- Legacy GI rail's amount pinned locally rather than left importing a renamed shared constant, specifically so a future rename of the free-participation constant can never silently change the legacy rail's charge
- Regression test reads `payment.ts` unfiltered by the comment-stripping `code()` helper, since its target there is intentionally a comment
