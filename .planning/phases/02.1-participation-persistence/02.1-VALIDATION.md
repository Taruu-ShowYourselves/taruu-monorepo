## Manual-Only Verifications

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| A real signed-in resident's vote persists end to end | VOTE-01, VOTE-03 | Requires a real session cookie, a verified-resident profile, and a live Supabase row read-back — not reproducible in a unit test with mocked `supabaseAdmin` | Sign in as a verified resident, vote on an active vote, then confirm a `user_votes` row exists for that `(user_id, vote_id)`, the chosen `vote_options.votes` incremented by exactly 1, and `votes.participant_count` incremented by exactly 1 |
| Receipt contains no seal or chain claim | VOTE-04 | Visual/RTL copy check | Complete a vote; confirm no `SealCard`, no `BLOCK` row, no `✓ חתום בבלוקצ׳יין`, and a status word that is not `נחתם` |
| Double-submit records exactly one vote | VOTE-02 | Genuine concurrency against the real `UNIQUE(user_id, vote_id)` constraint; the unit test can only simulate the violation | Double-click confirm (or fire two concurrent requests); confirm exactly one `user_votes` row and a tally that moved by exactly 1 |
| Mobile no longer advertises ₪3 | VOTE-05 | Requires the Expo app running | Open a vote in the mobile app; confirm the cost line matches the web model |
