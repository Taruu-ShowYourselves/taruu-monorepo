# Phase 02.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest 1.6.1 (`apps/web/package.json:86`) |
| **Config file** | `apps/web/vitest.config.ts` — `environment: 'node'`, `include: ['src/**/*.test.ts', 'src/**/*.spec.ts']` |
| **Quick run command** | `pnpm --filter @sync/web test -- <path>` |
| **Full suite command** | `pnpm --filter @sync/web test` |
| **Package checks** | `pnpm --filter @sync/shared typecheck` · `pnpm --filter @sync/api-client test` · `pnpm --filter @sync/mobile typecheck` |
| **Estimated runtime** | ~1s quick · ~60s full |

**Two constraints that shaped every choice below (verified 2026-08-02, not assumed):**

1. **There is no component-test setup.** `environment: 'node'`, no `jsdom`, no `@testing-library/react`, and the include glob does not even collect `.tsx`. Adding a DOM stack mid-P0 was rejected. Instead: the client's network logic is extracted into `submitParticipation.ts` (a `.ts` module with injected `fetch`) and unit tested for real, while the component's copy is asserted against SOURCE using the pattern the repo already established in `apps/web/src/__tests__/services/dashboard-free-mvp.test.ts`.
2. **A participate-route test file already exists.** `apps/web/src/__tests__/api/vote-participation.test.ts` — 694 lines, 30 passing tests, covering three routes. Its participate block locks in the payment contract (402, 503, `tokensEarned: 3`). It is **rewritten in place** by task `02.1-04-T1`; no new `votes-participate.test.ts` is created. The `verify-location` and `participated` describes in that file must survive untouched.

- **After every task commit:** run that task's `<automated>` command

- **Before `/gsd:verify-work`:** all four green

## Known Gaps Recorded, Not Closed Here

- **Mobile `handleVote` still routes to `/payment/checkout`** (`apps/mobile/app/vote/[id].tsx:163-173`) while the screen now advertises free participation. Deliberately deferred — rewiring mobile needs the Expo app exercised end to end. Flagged in plan 03.
- **Chain-seal copy on marketing surfaces** (`TrustBar`, `Hero/ConsensusVisual`, `VotesHero`, `ArchiveHero`, `PricingContent`, `about/Mission`, sign-in/sign-up, coin, treasury, verification pages) is outside the casting funnel and outside this P0. Recorded in plan 05's guard test header.
- **Votes cast between 2026-07-29 and this fix are unrecoverable.** No backfill is attempted — CONTEXT.md defers it explicitly as a data question.
- **`incrementVoteOption`'s RPC fallback is a non-atomic read-modify-write** (`db.ts:993-1005`). Untouched here; worth revisiting if launch volume creates concurrent votes on the same option.
