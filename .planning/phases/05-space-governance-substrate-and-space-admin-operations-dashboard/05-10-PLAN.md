<objective>
Move the ₪50 vote-creation charge from submission to approval, exactly as the locked user decision requires, and make submission free.

Purpose: putting creation behind review while still charging at submission would mean billing someone for something that can then be rejected — and this codebase has no refund or credit-note path. CONTEXT.md flags this reordering as a first-class task with its own tests, not a side effect of the review gate, because it rewrites the live create-vote path.

The charge is **client-orchestrated today**: the create-vote page calls `/api/payments/create` and redirects to a Green Invoice checkout before any vote row exists, and the payments return page finalises the draft afterwards. Freeing the server alone would leave the browser charging ₪50 at submission and approval charging ₪50 again. Both halves move in this plan, and the client half runs immediately after the server half so a partially-executed plan cannot leave a double-charge in the tree.
Output: a free submission path on both sides of the wire, a payment port, an implementation that works with today's rails, the approve-branch charge, and tests.
</objective>
