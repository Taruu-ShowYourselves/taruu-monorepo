# Phase 5 — UI Design Contract

> Visual and interaction contract for `/he/space-admin/[spaceId]`. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** SPACE-10 (the UI requirement) plus the UI-side obligations of SPACE-03 (object-level deny), SPACE-04 (reason required), SPACE-05 (review states), SPACE-06 (members, roles, and permitted-content controls), SPACE-07 (aggregates only), SPACE-08 (audience preview), SPACE-09 (suspension + escalation).

> **This contract is prescriptive.** Where it names a token, a size, a glyph, or a Hebrew string, that is the value to implement. Deviations need a spec amendment, not a judgement call at implementation time.

## Route + Shell Contract

Six surfaces = six routes, not six client tabs. Each surface resolves its own capability server-side, so the SPACE-03 headline test (swap `spaceId`, get `FORBIDDEN`) applies to every surface independently and every surface is directly linkable for its screenshot.

| Surface | Route |
|---------|-------|
| 1. Space overview | `/he/space-admin/[spaceId]` |
| 2. Proposal review | `/he/space-admin/[spaceId]/proposals` |
| 3. Members & roles | `/he/space-admin/[spaceId]/members` |
| 4. Statistics | `/he/space-admin/[spaceId]/stats` |
| 5. Notification composer | `/he/space-admin/[spaceId]/dispatch` |
| 6. Audit history | `/he/space-admin/[spaceId]/audit` |

**Shell** (shared layout at `app/[locale]/space-admin/[spaceId]/layout.tsx`), copying the `/he/knesset` reference implementation exactly:

```tsx
<div className="np-page">
  <Masthead locale={locale} />
  <main>
    <SpaceAdminHeader … />      {/* page masthead: kicker + h1 + edition meta */}
    <SpaceAdminNav … />         {/* six links, Segmented look, aria-current */}
    {children}
  </main>
  <Colophon locale={locale} />
</div>
```

- `Masthead` is **not** sticky/fixed — `main` takes no top offset.
- **Never write `var(--header-height)`.** That custom property is referenced in three existing stylesheets and is **defined nowhere in the repo**, so `calc(var(--header-height) + …)` is an invalid value and the whole declaration is dropped. Do not propagate the bug.
- Page inline padding is `--np-gutter` on a `max-width: var(--np-container)` wrapper (or the `.np-container` utility). Single source of truth.

**Sub-navigation** is a `<nav aria-label="ניווט לוח הניהול">` of six `next/link`s styled with the `Segmented` visual language (boxed row, ink hairlines between cells, active cell inverts to ink fill), carrying `aria-current="page"`. It does **not** use the `Segmented` component: that component emits `role="tablist"`/`role="tab"` with no `aria-controls`, no linked `tabpanel`, and no arrow-key roving focus — correct tab semantics without a real tabpanel would be a lie to assistive tech, and these are separate documents anyway. Below 768px the nav scrolls horizontally (`overflow-x: auto`, `scroll-snap-type: inline mandatory`) rather than wrapping.

## Spacing Scale

Every value is an existing token; all are multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--space-1` | 4px | Glyph-to-label gap, chip inline padding |
| `--space-2` | 8px | Kicker gap, mono meta separation, field label→control |
| `--space-3` | 12px | Table cell block padding, dense control padding |
| `--space-4` | 16px | Default element gap, table cell inline padding, box padding (mobile) |
| `--space-6` | 24px | Box padding (desktop), gap between panels |
| `--space-8` | 32px | Gap between surface sections, dialog plate padding |
| `--space-12` | 48px | Major surface break (header→content) |
| `--space-16` | 64px | Page block-end padding |

**Exceptions (declared, permitted):**

1. `--space-11` (44px) — minimum interactive target on touch: `min-block-size: var(--space-11)` on every table-row action, chip button, pagination control, and nav cell.
2. `--np-gutter` — `clamp(var(--space-6), 4vw, var(--space-16))`, page inline padding only. Already token-composed.
3. Border widths come from `--np-rule-hair` / `--np-rule` / `--np-rule-heavy` (1/2/4px). These are rules, not spacing.
4. `@media` breakpoints must be pixel literals (`768px`, `1024px`) — CSS media queries cannot read custom properties. This is the **only** permitted hardcoded length, it matches existing code (`apps/web/src/app/[locale]/dashboard/page.module.css`), and it is not a CLAUDE.md violation.

## Typography

Five sizes, one of them narrowly scoped. Heebo carries three weights, inherited from the locked system.

| Role | Token | Size | Family | Weight | Line height | Tracking |
|------|-------|------|--------|--------|-------------|----------|
| Kicker | `--text-xs` | 11.1px | JetBrains Mono | 700 | 1.2 | `0.12em`, uppercase |
| Mono data / label / meta / hint | `--text-sm` | 13.3px | JetBrains Mono | 500 data · 700 labels | 1.35 | `0.08em` on labels, `0.02em` on data |
| Body / button label / panel heading (`h2`) | `--text-base` | 16px | Heebo | 400 body · 800 heading + button | 1.5 body · 1.2 heading | `0` |
| **Page-primary button label only** | `--text-lg` | 19.2px | Heebo | 800 | 1.2 | `0` |
| Page headline (`h1`) + stat figure | `--text-3xl` → `--text-2xl` below 768px | 33.2 → 27.6px | Heebo | **900** (declared exception) | 0.95 | `-0.02em` |

**Two declared deviations from "four sizes, two weights per family", both inherited rather than invented:**

- `--text-lg` exists **only** on the page-primary `NewsButton size="lg"`, and it is there for contrast, not hierarchy: 19.2px at weight 800 clears WCAG's 18.66px large-text threshold, which is the sole reason a red button label is permitted at 4.03:1 (see D8). It is not available for headings, body, or any other control. Removing it would force red buttons below AA.
- Heebo weight **900** on `h1` and stat figures. Loaded in `globals.css:6` and already used across existing np pages — this is the locked system's display weight, not a new one. Heebo therefore carries 400 / 800 / 900 in this phase.

- **Standfirst** (one paragraph per surface, max 2 lines): `--np-font-body` (Frank Ruhl Libre) at `--text-base` / weight 400 / line-height 1.5. Family change only — no new size. This is the surface's one editorial line; everything else is Heebo or mono.
- Panel headings are `h2` at `--text-base`/800 preceded by a kicker and a `--np-rule-heavy`. In this design system, hierarchy is carried by rules and kickers, not by a size ladder. Do not invent intermediate sizes.
- All numerals in tables, figures, counters, quotas: `font-variant-numeric: tabular-nums`.
- Latin identifiers (uuids, hashes, ISO timestamps, `spaceId`) render inside `<span dir="ltr">` with `unicode-bidi: isolate` and `overflow-wrap: anywhere`, or they scramble in the RTL flow.
- Dates for humans: `toLocaleDateString('he-IL')`; audit timestamps: `toLocaleString('he-IL', { dateStyle: 'short', timeStyle: 'short' })`.

## Color

Two-colour print discipline: ink + one red on cream. **No third hue anywhere in this phase** — no green "approved", no amber "warning", no blue links.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--np-paper` | `#F4F1E8` | Page canvas, surface backgrounds |
| Secondary (30%) | `--np-paper-box` | `#FBFAF4` | Boxed furniture, panels, table rows |
| Secondary depth | `--np-paper-2` | `#ECE7D8` | Row hover, tally track, disabled fill, skeletons |
| Structure | `--np-ink` / `--np-ink-soft` / `--np-ink-faint` | `#14110E` / `#3B362E` / `#6E675A` | All type, all rules, table head block, ink buttons |
| Accent (10%) | `--np-red` | `#E0301E` | See reserved-for list |
| Accent, text-safe | `--np-red-ink` | `#7A1607` | **All red text below 18.66px** |
| Destructive | *no separate hue* | — | Differentiated structurally, see below |

**Accent (`--np-red`) reserved for, exhaustively:**

1. Kicker tick glyphs (`■` / `▍`) — decorative, `aria-hidden`.
2. The single page-primary action per surface (`NewsButton variant="red" size="lg"`). One per surface, never two.
3. Focus rings — `outline: var(--np-rule) solid var(--np-red); outline-offset: 2px` (system default, unchanged).
4. Invalid field border and the `role="alert"` rule (`PressInput` already does this).
5. The `בלתי הפיך` confirmation-plate rule (`--np-rule-heavy` in red).
6. `TallyBar` fill on the statistics surface.
7. The single status chip meaning "this needs your decision" (`בבדיקה`).

**Red is NOT used for:** row hover, links, zebra striping, disabled states, chart series, the `מושעה` chip (that is an inverted ink chip — "switched off", not "urgent"), or any second simultaneous status colour.

### Measured contrast rules (these are why the button sizes above are fixed)

Contrast is symmetric — a pair has one ratio regardless of which colour is foreground.

**On paper backgrounds:**

| Pair | Ratio | Verdict |
|------|-------|---------|
| `--np-ink` ↔ `--np-paper` | **16.66:1** | AAA |
| `--np-ink-faint` on `--np-paper` | 4.96:1 | AA normal text — safe for all mono meta |
| `--np-ink-faint` on `--np-paper-2` | **4.53:1** | AA normal text, by 0.03. **Nothing may darken `--np-paper-2`** — it carries row hover, the dimmed stale preview, and the disabled fill |
| `--np-red-ink` on `--np-paper` | 9.56:1 | AAA — **use this for every red string** |
| `--np-red-ink` on `--np-paper-box` | 10.32:1 | AAA |
| `--np-red-ink` on `--np-paper-2` | 8.73:1 | AAA |
| `--np-red` ↔ `--np-paper` | **4.03:1** | Fails AA normal text; passes large text (3:1) and non-text (3:1). A red button label must be ≥18.66px bold |

**On ink backgrounds** (`--np-block-ink`, the table head block, the suspended banner, `QuotaBlock`):

| Pair | Ratio | Verdict |
|------|-------|---------|
| `--np-paper` on `--np-ink` | **16.66:1** | AAA — **the only compliant text colour on ink** |
| `--np-red-ink` on `--np-ink` | **1.74:1** | **Fails everything.** Never |
| `--np-red` on `--np-ink` | **4.13:1** | Fails AA normal text. An 11.1px/700 kicker is normal text, not large — so this fails too |

**Consequences, binding:**

The red-text rule is **per background**, not global. Naming a token without naming its background is how the ink-block case slipped through:

- **On paper, paper-box, or paper-2** — red text at `--text-xs` / `--text-sm` / `--text-base` uses `--np-red-ink`. This includes kicker text: the shared `.np-kicker` utility paints text in `--np-red` (4.03:1), so this phase defines its own kicker CSS with `--np-red-ink` text and a `--np-red` tick glyph. Recorded as D9.
- **On ink** — kicker and banner **text** is `--np-paper` (16.66:1). Only the `■` / `▍` tick glyph stays `--np-red`; it is decorative, `aria-hidden`, and therefore exempt from the text-contrast threshold. There is no compliant red *text* on ink under either token, so do not attempt one.
- **`.np-block-red`** (red fill with paper text, `globals.css:482`) is **used nowhere in this phase.** It would put 13.3px paper text at 4.03:1. It is a tempting utility; it is out of bounds here.
- **The dispatch stale banner** is a `--np-red` rule (`--np-rule-heavy`, non-text, 3:1 threshold, passes) with `--np-red-ink` text on `--np-paper-2` — 8.73:1. It is **not** a red fill and **not** an ink block.
- A red `NewsButton` is only used at `size="lg"` (`--text-lg` = 19.2px at weight 800 → WCAG large text → 3:1 threshold → passes). Dense controls (table rows, dialog footers, pagination) use `variant="ink"` (16.66:1) or `variant="outline"` (16.66:1). There is no red dense button in this phase.

### Disabled-state contract (named, because `NewsButton` has none)

`NewsButton.module.css` contains **no `:disabled` rule at all**. A disabled button currently renders identically to an enabled one and keeps `cursor: pointer`. Rule B below rests on six enumerated `disabled` states, and screenshot #13 must show a *visibly* disabled confirm button as acceptance evidence — so the appearance has to be specified here or that evidence is unsatisfiable.

`NewsButton` stays on the "reused as-is, do not fork" list. The disabled appearance is a **phase-local override passed through its existing `className` prop**:

| Property | Value | Note |
|---|---|---|
| `background` | `var(--np-paper-2)` | The "disabled fill" the Color table already names |
| `color` | `var(--np-ink-faint)` | 4.53:1 on paper-2 — passes AA normal text |
| `border-color` | `var(--np-ink-faint)` | Keeps the boxed silhouette; no dashed or removed border |
| `cursor` | `not-allowed` | |
| `:hover` | **no inversion** | The enabled press affordance is ink-inversion on hover; a disabled control must not respond |
| `opacity` | **unset** | Do not dim. Opacity would drag paper-2 below its 0.03 AA margin |

Applies to every `disabled` in Rule B's list and to the `ConfirmDialog` confirm button. Because it lands on `--np-paper-2` at 4.53:1, **nothing in this phase may darken that token** — see the contrast table.

### New dependency

`@radix-ui/react-alert-dialog` — focus trap, `Escape`, `aria-describedby`, RTL, scroll lock. The repo already treats Radix as the behaviour layer painted with press tokens (`Masthead.tsx:48-51`: *"Radix DropdownMenu does the hard part … press tokens style it"*), and `@radix-ui/react-dropdown-menu@^2.1.22`, `react-tabs`, `react-progress`, `react-separator` are already dependencies. The alternative — hand-rolling like `GeoGate` — ships a dialog with no focus trap and no `Escape` handler, which is not acceptable for a destructive-confirmation surface. See Registry Safety.

## Interaction Contract 1 — Default-Deny UI

Two rules. They are disjoint and both are testable.

**Rule A — Authority: a control the admin does not hold the capability for is NOT RENDERED.** Never disabled, never greyed, never tooltip-explained.

- Rationale: a disabled control is unreachable by touch for its tooltip, leaks the shape of the capability model, and produces exactly the "broken page" the phase brief forbids.
- Absence is made legible — not mysterious — by the **capability manifest** on the overview surface, which lists every capability in the vocabulary with ✓ granted / ✕ not granted. Nothing is hidden; the admin always has one place that explains why a control is not on their page.
- A whole surface the admin lacks: its nav link is not rendered. Direct navigation to that route renders `NoPermissionPanel` inside the normal shell (the page is still coherent — masthead, nav, footer intact).
- UI hiding is presentation only. Every one of these routes and endpoints re-resolves the capability server-side; SPACE-03 is a server test, not a UI test.

**Rule B — State: `disabled` is reserved for transient, self-resolvable form state, and every disabled control carries visible text naming what unblocks it.**

Permitted `disabled` uses in this phase, exhaustively:

| Control | Disabled while | Visible unblock text |
|---------|----------------|----------------------|
| `ConfirmDialog` confirm | reason < 10 chars | `הנימוק נדרש כדי להמשיך.` |
| Dispatch send | no fresh audience preview | `חשבו קהל יעד כדי לאפשר שליחה.` |
| Dispatch send | preview returned 0 recipients | `אין נמענים מאושרים בקהל שבחרתם.` |
| Pagination "older" | on the last page | `זו הרשומה הישנה ביותר.` |
| Pagination "newer" | on the first page | `אתם בתחילת היומן.` |
| Any submit | request in flight | button label swaps to `…שולח` / `…שומר` |

Any other disabled control is a spec violation.

## Interaction Contract 2 — Confirmation + Required Reason

Every authority-changing action goes through `ConfirmDialog`. The reason lives **inside the dialog**, above the confirm button — not in the row, not in a second step, not in a toast. It is a server requirement (SPACE-04), so the UI must make it structurally impossible to submit without it.

**Anatomy** (Radix `AlertDialog`, press-painted):

```
┌─ plate: --np-paper-box, border: --np-rule-heavy solid {ink|red}, radius 0, padding --space-8
│  ■ kicker (mono, --text-xs, --np-red-ink)      ← "פעולה מתועדת" | "פעולה בלתי הפיכה"
│  h2  (Heebo 800, --text-base)                  ← the question
│  p   (Heebo 400, --text-base, --np-ink-soft)   ← what happens
│  p   (mono, --text-sm, --np-red-ink)           ← irreversible kind only: the consequence line
│  ─── --np-rule hairline ───
│  PressInput multiline, label "נימוק ההחלטה (חובה)"
│  mono counter --text-sm --np-ink-faint         ← "{n}/500"
│  ─── --np-rule hairline ───
│  [ NewsButton ink  = confirm ]  [ NewsButton outline = ביטול ]
└─
```

| Property | Value |
|----------|-------|
| Backdrop | `--color-surface-overlay` (`rgba(0,0,0,0.5)`), `z-index: var(--z-modal-backdrop)`; plate at `var(--z-modal)` |
| Plate rule — `kind="audited"` | `--np-rule-heavy` `--np-ink`, kicker `פעולה מתועדת · AUDITED` |
| Plate rule — `kind="irreversible"` | `--np-rule-heavy` `--np-red`, kicker `פעולה בלתי הפיכה · IRREVERSIBLE`, plus the consequence line |
| Initial focus | the **reason textarea** — never the confirm button |
| Reason validation | required, trimmed length 10–500. Error: `נדרש נימוק — לפחות 10 תווים.` Live counter, no hard truncation on paste (block submit instead) |
| Confirm button | `NewsButton variant="ink"`, `disabled` until reason valid, label = the action verb (never "אישור"/"OK") |
| Cancel | `NewsButton variant="outline"`, label `ביטול`. `Escape` and backdrop click both cancel |
| Open/close motion | hard inset clip reveal, `--np-dur` 200ms `--np-ease`. No fade+scale, no bounce. Under `prefers-reduced-motion` the plate appears with no transition |
| On success | dialog closes, the affected row updates in place and receives a 1200ms `--np-paper-2` flash (skipped under reduced motion), and an `aria-live="polite"` node announces the result |
| On failure | dialog **stays open**, reason preserved, error rendered inside the plate as `role="alert"` in `--np-red-ink`. Never lose typed text |

**Which action gets which kind:**

| Action | Kind | Trigger button in row |
|--------|------|----------------------|
| אישור ופרסום (approve + publish) | audited | `ink` |
| החזרה לתיקון (request changes) | audited | `outline` |
| הענקת הרשאה (grant capability) | audited | `ink` |
| דחיית הצעה (reject) | **irreversible** | `outline` |
| שלילת הרשאה (revoke capability) | **irreversible** | `outline` |
| השעיית חבר במרחב (suspend member) | **irreversible** | `outline` |
| שליחת התראה (send notification) | **irreversible** | page-primary `red` `lg` |

No destructive action is ever a filled block inside a table row. The only filled red block on any surface is that surface's single page-primary action.

## Interaction Contract 3 — Notification Composer Gating

The audience preview is the safety mechanism (SPACE-08). The UI enforces that the send request carries the *same* audience the admin was shown.

**State machine — the send control's availability is derived, never free:**

| # | State | What is shown | Send control |
|---|-------|---------------|--------------|
| 0 | `quota_exhausted` | `QuotaBlock` (ink block, red kicker `מכסה מוצתה · QUOTA`, reset date). Composer fields render **read-only** | **Not rendered at all** |
| 1 | `draft` | Composer fields + `חשבו קהל יעד` (`outline`). Quota line always visible: `מכסה חודשית · {used}/{limit}` | `disabled`, hint `חשבו קהל יעד כדי לאפשר שליחה.` |
| 2 | `previewing` | Preview panel `aria-busy="true"`, mono `…מחשב קהל יעד` | `disabled` |
| 3 | `preview_fresh` | `AudiencePreview` `Receipt` populated, `aria-live="polite"` | **Enabled** — `red` `lg`, label `שלחו התראה` |
| 4 | `preview_stale` | Preview panel dimmed to `--np-paper-2` + red banner `ההודעה שונתה אחרי חישוב הקהל — חשבו שוב לפני שליחה.` | `disabled` |
| 5 | `preview_empty` | Preview panel showing 0 approved recipients | `disabled`, hint `אין נמענים מאושרים בקהל שבחרתם.` |
| 6 | `sent` | Send `Receipt` replaces the composer; `שליחת התראה נוספת` (`outline`) resets to state 1 with fresh quota | not applicable |
| 7 | `send_failed` | `role="alert"` panel, composer content preserved | back to state 1; preview must be recomputed |

**Staleness rule:** any change to title, body, or audience selector transitions 3 → 4 immediately (on change, not on blur). The client holds the server-issued `previewToken` from the preview response and sends it with the send request; the server rejects a token that does not match the current payload. The UI never computes the audience itself.

**`AudiencePreview` — `Receipt` rows, in this order, always all four rendered (zeros included; a missing row reads as "not checked"):**

| Row label | Value |
|-----------|-------|
| `נמענים מאושרים` | `{n}` — `strong` row |
| `הוחרגו — ביטלו הסכמה` | `{n}` |
| `הוחרגו — ללא ערוץ פעיל` | `{n}` |
| `מכסה חודשית` | `{used}/{limit}` |

Receipt footer (mono, `--np-ink-faint`): `התצוגה חושבה ב־{HH:MM} · הנמענים שיקבלו בפועל זהים לרשימה שחושבה כאן.`

**Quota-exhausted composer** (state 0) — the send control is *absent*, not disabled, because it is not self-resolvable within the session; this is the one place where absence and Rule B agree. The block reads:

## Interaction Contract 4 — `PressTable` (RTL data tables)

Used by proposals, members, and audit. One implementation, three column sets.

**Semantics — non-negotiable:**

```html
<div class={scroller} role="region" aria-labelledby={captionId} tabindex="0">
  <table>
    <caption id={captionId} class={srOnly}>{description}</caption>
    <thead><tr><th scope="col">…</th></tr></thead>
    <tbody><tr><th scope="row">{primary}</th><td>…</td></tr></tbody>
  </table>
</div>
```

- The scroll container gets `tabindex="0"` + `role="region"` + a label so keyboard users can reach an overflowing table. Apply this **only when the table actually overflows** (measured), otherwise it adds a pointless tab stop.
- Never change a cell's `display` to `block`/`flex` — that destroys table semantics in assistive tech. Responsive column reduction is done by `display: none` applied to the **matched pair** (`th[data-col=x]` and `td[data-col=x]`), which keeps the table coherent.
- `text-align: start` on every cell, including numeric. `font-variant-numeric: tabular-nums` on dates, counts, and ids.

**Visual contract** (mirrors the existing `.record` pattern in the dashboard):

| Element | Style |
|---------|-------|
| `thead th` | `--np-block-ink` (ink fill, paper text), mono `--text-sm`/700, `letter-spacing: 0.08em`, uppercase, `position: sticky; inset-block-start: 0` on desktop |
| `tbody tr` | `--np-paper-box`, separated by `border-block-start: var(--np-rule-hair) solid var(--np-paper-edge)`; first row no rule |
| Row hover | `background: var(--np-paper-2)`. No zebra striping — press uses rules, not stripes |
| Row focus-within | `outline: var(--np-rule) solid var(--np-red); outline-offset: -2px` |
| Cell padding | `--space-3` block / `--space-4` inline |
| Row min height | `--space-11` (44px) |
| Table border | `--np-rule` solid `--np-ink` around the whole table |

**Column priority — pairs hidden below 768px:**

| Table | Always visible | Hidden < 768px |
|-------|----------------|----------------|
| Proposals | title (`th scope=row`), status, actions | submitter, submitted date |
| Members | member (`th scope=row`), status, actions | joined date, capability count |
| Audit | when, action, reason | actor, object, prior→new state |

When columns are hidden, the hidden values must still be reachable: the row's disclosure (`▾ הצג פרטים`) expands a `<tr>` with `<td colspan={n}>` containing a mono definition list of every hidden field. Same mechanism as the long-reason disclosure below, so there is one expansion pattern, not two.

**Long content:**

| Case | Treatment |
|------|-----------|
| Audit reason | 2-line clamp (`-webkit-line-clamp: 2` + standard `line-clamp: 2`, `overflow-wrap: anywhere`) with a `הצג נימוק מלא ▾` / `הסתר ▴` disclosure button (mono, `--text-sm`, ink, red underline on hover). Expanded text lives in the expansion `<tr>`, so the row height never breaks and the table never reflows sideways |
| Proposal title | 2-line clamp, full text in the expansion row |
| Member display name | 1-line clamp, `overflow-wrap: anywhere`, `title` attribute carries the full value |
| uuid / hash | `{id.slice(0,8)}…` in mono, `dir="ltr"`, `unicode-bidi: isolate`, `title` = full value, full value in the expansion row |

**Pagination — cursor, never offset:**

- The audit log is append-only and continuously written; an offset page 2 would duplicate or skip rows as new entries land. Cursor (keyset) pagination on `(created_at, id)` is the only safe option and the only one the UI offers.
- Controls, block-end, mono, `NewsButton variant="outline" size="sm"` with `min-block-size: var(--space-11)`:
  - `← רשומות ישנות יותר` (forward in RTL is toward the inline-end/left)
  - `רשומות חדשות יותר →`
- Meta line between them: `מוצגות {n} רשומות` for audit (**no total** — counting an append-only log is expensive and stale on arrival). Members shows a real total: `{n} חברים במרחב`.
- Cursor and filters live in the URL query (`?status=…&cursor=…`) so a filtered view is linkable, back-button-correct, and screenshot-reproducible.
- Truncation notice when a hard cap is hit: `מוצגות {n} הרשומות האחרונות. לרשומות ישנות יותר — המשיכו בדפדוף.`
- Mobile overflow hint, rendered only when the scroller actually overflows: `החליקו לצדדים לצפייה בכל העמודות` (mono, `--text-sm`, `--np-ink-faint`).

## Interaction Contract 5 — Aggregate-Only Statistics (SPACE-07)

The statistics surface must not imply a drill-down the API will refuse.

**Forbidden on this surface:** clickable stat cards, `<a>` or `<button>` wrapping any figure, hover states on figures, chevrons/`←` glyphs on cards, "צפו בפירוט" affordances, any per-resident row, any name, any identity field, any map pin, any export control.

**Required:**

- Every figure is a plain `<span>` inside a non-interactive card. `cursor: default`. No `:hover` rule on `.statCard` at all.
- **k-anonymity floor of 5**: any bucket with 1–4 residents renders the literal string `<5` in mono, with the note `מוסתר — קבוצה קטנה מדי` beneath it in `--text-sm` / `--np-ink-faint`. The client never receives the true small number; the UI simply must render what the API returns without inventing a fallback zero.
- A genuine zero renders `0`. A figure the API could not compute renders `—` with `הנתון לא זמין` — never `0`. (Dashboard precedent: `ComingSoonStat` exists precisely because a fabricated `₪0` is indistinguishable from a real empty value.)
- Surface footer note, always present, `--np-font-body`, `--text-base`:
  > כל המספרים כאן מצטברים. אין בלוח הזה פילוח או צפייה ברמת תושב יחיד — לא במסך ולא ב־API שמאחוריו.
- Bars use `TallyBar` (red fill, `--np-paper-2` track) and always carry the numeric value in mono beside them — never a bar alone.

**Suspension is reversible — `kind="audited"`, not `kind="irreversible"` (FLAG-4 resolution).** Per CONTEXT.md, suspension sets a nullable `suspended_at`; clearing it restores access. Filing it under the `פעולה בלתי הפיכה · IRREVERSIBLE` plate was wrong on the facts, and it devalued that plate for **reject**, which genuinely is terminal. In this phase only reject carries `kind="irreversible"`.

A suspended member's row shows the `מושעה/ית` chip (inverted ink) and offers **`ביטול השעיה`** in place of `השעיה במרחב`; grant and revoke are not rendered while suspended, because changing the capabilities of a member who cannot act is meaningless and would produce confusing audit rows. Screenshot #6 must show this row in its suspended state with the reinstate action present.

## Accessibility Contract

- **Landmarks:** one `<main>` from the shell; each surface is a `<section aria-labelledby>` pointing at its `h2`. Sub-nav is `<nav aria-label="ניווט לוח הניהול">`.
- **Heading order:** `h1` (shell, once) → `h2` (surface) → `h3` (panels within a surface). Never skip a level.
- **Focus:** visible on everything, `outline: var(--np-rule) solid var(--np-red); outline-offset: 2px`. Never `outline: none` without a replacement.
- **Dialog:** Radix AlertDialog handles trap / `Escape` / restore. Initial focus on the reason textarea. `aria-labelledby` = heading, `aria-describedby` = body paragraph.
- **Announcements:** `aria-live="polite"` for audience-preview results, save/send success, and skeleton→loaded. `role="alert"` for errors (`PressInput` already does this for field errors).
- **Tables:** `caption`, `scope` on all headers, row header on the primary cell, labelled focusable scroll region when overflowing.
- **Targets:** `min-block-size: var(--space-11)` (44px) on every interactive element at mobile widths.
- **Contrast:** every pair in the Color section above, measured. Red text below 18.66px is a defect.
- **Glyphs:** `■ ▍ ● ✓ ✕ ← → ▾ ↗` are decorative and always `aria-hidden`; the meaning lives in adjacent text. Never a glyph-only button.
- **RTL:** logical properties only. Latin ids/hashes/ISO timestamps wrapped `dir="ltr"` + `unicode-bidi: isolate`.

## Decisions Made in This Spec (no interactive session available)

Each was open; each is resolved toward the existing locked press system.

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Shell uses `np-page` + press `Masthead` + `Colophon`, **not** `@/components/layout/Header`/`Footer` | Header/Footer contain 0 `--np-*` and 34 `--lc-*` refs — Luminous Civic is explicitly deprecated in `.redesign/NEWSPRINT_TECH.md`. `/he/knesset` and `/he/municipality/[slug]` are the np-native reference shells |
| D2 | Never reference `var(--header-height)` | Referenced in 3 stylesheets, **defined nowhere** — the whole `calc()` declaration is invalid and silently dropped. Existing latent bug; do not copy it |
| D3 | Six routed sub-pages, not six client tabs | Each surface then carries its own server-side capability check and its own URL, which is what SPACE-03's "swap the spaceId" test and #75's per-surface screenshot evidence both need |
| D4 | Sub-nav is `<nav>` + links with `aria-current`, not the `Segmented` component | `Segmented` emits `role="tab"` without `aria-controls`, a linked `tabpanel`, or arrow-key roving focus. Borrowing its look is right; borrowing its ARIA would be a false promise to assistive tech |
| D5 | Unavailable-by-capability controls are **absent**, never disabled — paired with a mandatory capability manifest on the overview | Disabled controls are unreachable by touch for their explanation and leak the capability model. Absence + one authoritative "here is what you hold" panel is coherent without being mysterious |
| D6 | `disabled` is reserved for transient form state and always carries visible unblock text | Keeps D5 unambiguous: absence means authority, disabled means "not yet" |
| D7 | No separate destructive hue; danger is structural (red 4px plate rule + `בלתי הפיך` kicker + required reason + `outline` row trigger) | The locked system forbids a third hue and already spends red on the primary participate action, so red cannot also mean "danger" |
| D8 | Red buttons only at `size="lg"`; dense controls use `ink`/`outline` | `--np-paper` on `--np-red` measures 4.03:1 — below AA for normal text, above the 3:1 large-text threshold only at ≥18.66px bold |
| D9 | Red **text** uses `--np-red-ink` (9.56:1) **on paper backgrounds**, including kicker text; `--np-red` stays on the tick glyph | The shared `.np-kicker` utility paints text at 4.03:1. This phase does not propagate that; it scopes the fix to its own modules rather than editing a global used by every existing surface |
| D16 | The red-text rule is stated **per background**. On ink, kicker and banner text is `--np-paper`; only the tick glyph stays red. `.np-block-red` is used nowhere in this phase | D9 named a token without naming a background, and applied literally to `QuotaBlock`'s ink fill it produced `--np-red-ink` on `--np-ink` = 1.74:1. `--np-red` on ink is 4.13:1, which also fails for an 11.1px kicker. There is no compliant red text on ink, so the rule must name the background |
| D17 | Disabled appearance is a named phase-local contract applied through `NewsButton`'s `className` — paper-2 fill, faint text, `not-allowed`, no hover inversion, no opacity | `NewsButton.module.css` has no `:disabled` rule at all, so Rule B's six disabled states and screenshot #13's "confirm disabled" evidence were both unsatisfiable. Opacity is excluded because it would drag paper-2 below its 0.03 AA margin |
| D18 | Permitted-content controls (hide / unhide / flag) live on the proposal detail view, not a seventh route | User decision recorded in CONTEXT.md. The capability `לנהל תוכן מותר` was advertised in the manifest with nowhere to act — Rule A's incoherence inverted. Folding it here keeps six surfaces while giving SPACE-06 a real home |
| D19 | Suspension is `kind="audited"`, not `kind="irreversible"`, and a reinstate action exists | Suspension sets a nullable `suspended_at` and is reversible by definition. Mislabelling it devalued the irreversible plate for reject, which is the one genuinely terminal action in this phase |
| D20 | Self-submitted proposal actions are **absent** (Rule A), not disabled | This is object-level authority, not transient form state. Rule B's list is exhaustive and excludes it, and a disabled control would imply the admin could unblock it themselves |
| D21 | Escalation resolves to an audited `ConfirmDialog` writing a server-side record, exempt from the space quota, rendered regardless of capability | SPACE-09 requires a real path. A `mailto:` leaves no record, and an escalation about a wrongly-suspended admin is exactly the case that needs one — and the people who most need the control are those holding nothing |
| D10 | Cursor pagination, no total count on audit | The audit log is append-only and continuously written; offset paging duplicates and skips rows, and a total is expensive and stale on arrival |
| D11 | Table semantics preserved at all widths; responsive reduction via paired `display:none` + a row disclosure | Switching cells to `display:block` destroys table semantics in assistive tech — the usual "responsive table" trick is an a11y regression |
| D12 | Add `@radix-ui/react-alert-dialog` | The repo's own precedent (`Masthead.tsx:48-51`) is Radix-for-behaviour + press-tokens-for-paint. The in-repo hand-rolled alternative (`GeoGate`) has no focus trap and no `Escape` handler — unacceptable for destructive confirmation |
| D13 | k-anonymity floor of 5 on the statistics surface, plus `—` for unavailable and `0` only for a true zero | SPACE-07 is aggregates-only; a bucket of 2 is effectively identifying. Dashboard precedent already refuses to print a fabricated zero |
| D14 | Composer holds a server-issued `previewToken`; any content change invalidates it | The UI must not be able to send an audience different from the one it displayed — SPACE-08's delivered-equals-previewed guarantee has to be structural, not procedural |
| D15 | Type ramp constrained to the press ladder, with hierarchy carried by kickers and rules. `--text-lg` is declared but scoped to the page-primary button only, and Heebo's 900 weight is inherited from the locked system | Matches how the press system already works; avoids inventing an admin-only type ladder inside a locked design language. `--text-lg` is contrast-driven rather than hierarchical — it is what lets a red button clear the 18.66px large-text threshold under D8 |
