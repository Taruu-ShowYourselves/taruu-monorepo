A `<tr>` rendered immediately after a proposal's row, with a single `<td colSpan={n}>` holding the panel. Table semantics are preserved — this is the same device as the responsive row disclosure, reused at every width rather than only below 768px. On the proposals table the detail panel **is** the row disclosure; the generic `הצג פרטים ▾` mechanism is not additionally rendered here, so there is exactly one `<tr>` expansion per row at every width.

Contents, in this order:
1. Full proposal title as `h3`, Heebo 800, `--text-base`.
2. Submitter and submission timestamp, mono meta.
3. The hidden and flagged notice lines if present — hidden first when both apply.
4. The proposal body: `--np-font-body` (Frank Ruhl Libre), `--text-base`, line-height 1.5, `max-width: 68ch`. Long bodies clamp at 12 lines behind `הצג את הטקסט המלא ▾` / `הסתר ▴`. That string is deliberately distinct from every other expander on the surface: this one sits *inside* the panel the title button opened, and two nested disclosures sharing an accessible name is a screen-reader defect.
5. A `--np-rule` hairline.
6. The content controls.

The controls, when and only when the admin holds `content.moderate` — otherwise they are absent (Rule A) and the panel still opens so the admin can read the proposal. Hide and unhide are mutually exclusive, and so are flag and unflag: a hidden item offers `ביטול הסתרה` and never `הסתרת תוכן`; a flagged item offers `ביטול סימון` and never `סימון לבדיקה`. All four are `NewsButton variant="outline"` and all four route through `ConfirmDialog` with `kind="audited"` — each has an inverse in this same panel, so none is irreversible.

Below 768px the panel additionally carries the hidden-column definition list, so values dropped from the table stay reachable.

Keyboard: `Escape` collapses the panel and returns focus to the title button.

Props: `{ proposal: ProposalDetail; canModerate: boolean; spaceId: string; onModerated: () => void; panelId: string; columnCount: number }`.

`page.tsx` — Server Component. Awaits `params` and `searchParams`, calls `listSpaceProposals` (the same use-case the API route calls, never a db helper), renders `SpaceAdminHeader`, `SpaceAdminNav`, the kicker, the standfirst, and hands the data to `ProposalsClient`. On `FORBIDDEN` it renders `NoPermissionPanel` with the escalation CTA, exactly as the overview does.

`ProposalsClient.tsx` — a client island holding the interactive parts:

**Filters.** Five, defaulting to `בבדיקה`. Filter state lives in the URL query (`?status=…`), so a filtered view is linkable, back-button-correct and screenshot-reproducible.

**Table.** `PressTable` with the five columns. Always visible: title (`th scope="row"`), status, actions. Hidden below 768px: submitter, submitted date — as matched `data-col` pairs, with the values reachable in the detail panel. The caption string is the Surface 2 caption from the copy deck.

**Row actions.** Three `NewsButton`s: `אישור ופרסום` as `variant="ink"`, `החזרה לתיקון` and `דחייה` as `variant="outline"`. No destructive action is ever a filled block inside a table row, and this surface has no page-primary red button at all — `אשרו ופרסמו` is the headline decision but it is a dialog confirm, not a hero action.

Each opens `ConfirmDialog`: approve and reject with `kind="irreversible"` (approve publishes to residents and fires the charge; reject is terminal), request-changes with `kind="audited"` (the submitter can resubmit). Use the copy triples from the interfaces block verbatim.

**Self-submitted rows.** The three decision actions are **not rendered** — this is object-level authority, not transient form state, so Rule A governs and Rule B's disabled list does not include it. The lock text `הצעה שהגשתם — ההכרעה שמורה למנהל אחר.` occupies the actions cell instead. A disabled control here would wrongly imply the admin could unblock it themselves. The detail panel still opens and content controls still apply — the restriction is on deciding one's own proposal, not on moderating its content.

**Detail panel.** The proposal title cell is the **only** trigger: a `<button>` whose accessible name is the proposal title, carrying `aria-expanded` and `aria-controls` pointing at the panel id. There is no separate expand button and no second toggle label. Opening one panel closes any other, so two reason fields are never open at once.

**Deep link.** `?proposal={id}` opens the surface with that panel expanded and scrolled into view. Because Surface 2 defaults to the `בבדיקה` filter and audit-log subjects are *decided* proposals the default view excludes, `?proposal={id}` must **force the filter to `הצגת הכול`** before expanding, or the panel would silently fail to open. An id that does not exist or is outside this space renders the surface normally with `ErrorPanel` copy `ההצעה לא נמצאה במרחב הזה.` — never a cross-space disclosure.

**Outcomes.** On success the dialog closes, the affected row updates in place and gets a 1200ms `--np-paper-2` flash (skipped under `prefers-reduced-motion`), and an `aria-live="polite"` node announces the matching string from the copy deck. On a 409 render the decision-conflict panel with `רענון הרשימה`. On a 402 keep the dialog open with the reason preserved and render the charge-failure string as `role="alert"` inside the plate.

**States.** Loading is five skeleton rows with `aria-busy`. Empty is `EmptyPanel` with `אין הצעות בבדיקה` / `כשתושב יגיש הצעה חדשה במרחב הזה, היא תופיע כאן להכרעה.` A filter that matches nothing is the separate no-results state with `הצגת הכול`.
