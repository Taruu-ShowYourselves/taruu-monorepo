```ts
/**
 * Escalation is reachable by a suspended admin and by a user holding nothing.
 * Gating it on a capability would put the control out of reach of exactly the
 * people who need it. It is rate-limited per user instead, and is exempt from
 * the per-space notification quota.
 *
 * RULE 1 — It writes ONLY to platform_escalations. It never writes a row into
 * the target space's space_audit_log. That log is append-only and enforced by
 * a trigger, so an endpoint any authenticated user can reach would let anyone
 * permanently append rows to an arbitrary space's audit history at 5/hour,
 * with no path to ever clean them up. Escalations are platform correspondence,
 * not space governance events; they belong in the platform table.
 *
 * RULE 2 — Its response is a single opaque acknowledgement, identical in every
 * case: whether the space exists or not, whether the caller is a member or
 * not, whether they are suspended or not, and whether the id is a well-formed
 * uuid or garbage. There is NO branch observable to the caller. Distinguishing
 * an existing foreign space from a nonexistent one would contradict 05-04's
 * must-have (malformed, nonexistent, unauthorised and suspended all answer
 * alike) and SPACE-03's "no data disclosed in the error".
 */
```

Implementation, and the ordering is what makes Rule 2 true:

1. Parse the body with `EscalationRequestSchema` (a body under 10 characters is a 400 — that is a property of the caller's own input, not of the target, so it discloses nothing).
2. Attempt `resolveMembership(session, rawSpaceId)`. On success take `membership.spaceId`; on **any** failure take `null`. Do not inspect the error, do not look the space up separately, do not check whether the uuid is well-formed as a separate branch. One `.unwrapOr(null)`-shaped call, no `if` on the reason.
3. `insertEscalation({ spaceId, rawSpaceId, raisedBy: session.userId, body: cmd.body })`. Because `platform_escalations.space_id` is nullable and `raw_space_id` is a plain `TEXT`, this insert succeeds in every case listed in the `<behavior>` block — member, non-member, suspended, foreign space, nonexistent uuid, malformed id — so the caller cannot tell them apart by status code or by which branch ran.
4. Return the constant acknowledgement — a 202 with a fixed body. Do **not** echo the space name, the space id, or anything resolved in step 2.
5. **No `insertAuditRow` call anywhere in this file.**

Three cases deserve explicit construction rather than a generic loop:

1. **Suspension does not erase history.** In one test: suspend a member, then assert (a) `findActiveGrant` for that user now resolves null so the next request is 403, and (b) `listAuditRows` still returns their earlier `proposal.approved` row.
