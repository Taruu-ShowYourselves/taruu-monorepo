```ts
}
```

`identity_verified_at` is read only to be turned into a boolean in the use-case — never returned as a timestamp. Note that in a comment.

Also: `countSpaceMembers(scope)`, `listGrantsForSpace(scope, userIds)` (batched, so the members table is not an N+1), and `listActiveMemberSuspensions(scope, userIds)`.

Mutations, all scope-typed and all returning the affected row so the use-case can build the audit `prior_state` / `new_state`:
- `insertGrant(scope, { userId, capability, grantedViaRole })` — inserts with `granted_by: scope.userId`. Rely on `uq_active_grant` for idempotency: a unique-violation must be mapped to `conflict('ההרשאה כבר קיימת.')`, not a 500.
- `revokeGrant(scope, { userId, capability })` — a conditional update setting `suspended_at = now(), suspended_by = scope.userId` guarded by `.is('suspended_at', null)`; zero rows means it was already revoked and returns `conflict`. Revocation is a suspension write, never a `DELETE` — deleting the row would erase the fact that the capability was once held.
- `suspendGrantById(spaceId, grantId, actorUserId)` — the platform-admin path. This one deliberately takes plain ids and **not** a `SpaceScope`, because a platform admin holds no space capability and therefore cannot mint one. It must carry a comment saying exactly that, and the calling use-case is responsible for the `is_platform_admin` check.
- `suspendMember(scope, { userId, reason })` — two writes: insert into `space_member_suspensions`, then set `suspended_at`/`suspended_by` on **all** of that user's active grants in this space. Guard the insert with `uq_active_member_suspension`; a unique violation is a `conflict`.
- `reinstateMember(scope, { userId })` — set `lifted_at`/`lifted_by` on the active suspension row and clear `suspended_at`/`suspended_by` on that user's grants in this space.
- `setContentModeration(scope, voteId, action)` where action is `'hide' | 'unhide' | 'flag' | 'unflag'`. Each is a conditional update carrying the space predicate and the current-state guard in the same statement, so hide-on-already-hidden is a `conflict` rather than a silent no-op:

```ts
  // unhide: .not('hidden_at', 'is', null).update({ hidden_at: null, hidden_by: null })
```
- `insertEscalation({ spaceId, raisedBy, body })` — takes plain ids, because the escalation path is reachable by a user holding no capability and therefore no scope. Comment it.
- `isPlatformAdmin(userId)` — `select('is_platform_admin').eq('id', userId).maybeSingle()`.
