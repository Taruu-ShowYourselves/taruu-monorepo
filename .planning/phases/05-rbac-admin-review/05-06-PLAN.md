<objective>
Ship the admin review console — the screen ROADMAP criterion 3 requires, where an admin sees a
pending community-manager application and approves or rejects it with a recorded reason.

Purpose: this is the human half of RBAC-03. It is deliberately built as a **generic reviewed-claim
console** rather than a community-manager-specific screen, because GitHub issue #76's authority
onboarding must reuse it (CONTEXT.md forward-compatibility constraint 2).

Security posture: this console is an unlisted route with **no client-side gating**. It renders,
calls the API, and shows an access-denied state when the server returns 403. That is the correct
model — authorization is never inferred client-side (RBAC-02), and the page deliberately does not
read `user.roles` to decide whether to render.

Output: one page + its CSS module.
</objective>

`decide(app, decision)`:
```tsx
setPendingId(app.id); setSuccessMessage(null); setErrorMessage(null);
try {
  const response = await fetch(`/api/admin/manager-applications/${app.id}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ decision, reason: (reasons[app.id] ?? '').trim() }),
  });
  const data = await response.json().catch(() => ({}));
  if (response.ok) {
    setApplications((list) => list.filter((a) => a.id !== app.id));
    setSuccessMessage(
      decision === 'approve'
        ? 'הבקשה אושרה. ההרשאה נוצרה — היא עדיין כפופה לכל התנאים.'
        : 'הבקשה נדחתה והנימוק נשמר.'
    );
  } else if (response.status === 409) {
    setApplications((list) => list.filter((a) => a.id !== app.id));
    setErrorMessage('הבקשה כבר טופלה על ידי מנהל אחר.');
  } else if (response.status === 403) {
    setErrorMessage('אין לכם הרשאה לפעולה הזו.');
  } else {
    setErrorMessage(data.error || 'שגיאה בשמירת ההחלטה');
  }
} finally {
  setPendingId(null);
}
```

The approve success string must be exactly

load-bearing property to the reviewer.
