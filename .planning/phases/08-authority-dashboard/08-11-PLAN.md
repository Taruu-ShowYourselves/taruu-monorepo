**States:** 401 → `נדרשת התחברות`; 403 → `אין לכם גישה למרחב הרשות.`; 200 → the inbox.

**Filter tabs** using the existing `Tabs` or `Segmented` component: `ממתינות לתגובה` ·
`נענו` · `הכול`. Default to `ממתינות לתגובה` — the inbox's job is to make the unanswered set
obvious, and defaulting to "all" buries it.

**Each row:** title, status badge (`פתוחה` / `סגורה`), the closing date, the participant count, the
winning option when closed, and the response state — `לא נענתה`, or
`נענתה · גרסה {version}` (`הוסרה` when retracted).

**The composer**, opened per row:
1. `GET /api/authority/votes/[id]/response` to load the current version and its history.
2. A textarea prefilled with the current text when revising, with a 20–5000 character counter (UX
   only; the server enforces it).
3. **Before the submit button**, when a version already exists, an unmissable line:
   `פרסום גרסה חדשה אינו מוחק את הגרסה הקודמת. הגרסה {n} תישאר גלויה לתושבים עם שמכם והתאריך.`
   That sentence is the whole point of AUTH-04 made visible to the person it constrains — an author
   who believes they are editing in place will write differently from one who knows the old text
   stays up.
4. An optional `הערת עדכון` (revision note) field, labelled `מה השתנה? (יוצג לתושבים)`.
5. A `הסרת התגובה` action that publishes a `retracted` version, with its own confirmation:
   `הסרה מפרסמת גרסה חדשה המסומנת כמוסרת. הטקסט הקודם יישאר גלוי.`
6. A preview rendered through `OfficialResponseBlock` (or its props shape), so the author sees what a
   resident will see, including the verified badge and the byline.
7. **Version history**, newest first, each entry with its author, date, note and text.

Map 409 → `התגובה עודכנה בינתיים על ידי נציג אחר. רעננו וכתבו מחדש.` and 403 `cross_municipality` →
`ההצבעה הזו אינה של הרשות שלכם.` Never auto-retry a 409 — publishing a revision against text the
author never read is exactly the failure the version index exists to prevent.
