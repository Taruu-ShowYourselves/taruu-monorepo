   never automatic; the copy must not undercut it.
3. **Claim `approved` / `rejected`** → show the outcome and the recorded `reviewReason` verbatim,

- `claimedRoleHe` — `תפקידכם ברשות`
- `motivation` — textarea, `למה אתם הגוף המוסמך?`, with a live character counter enforcing 40–2000

- `evidenceUrls` — up to 5 URL inputs, `קישורים לאימות (עד 5)`, with helper text naming what is
  useful: `למשל: עמוד רשמי באתר הרשות, פרוטוקול מועצה, או דף צוות שמופיע בו שמכם.`

  <action>
Create the review console as a client component, Hebrew and RTL.

**Security posture — copy Phase 5's exactly and comment it at the top of the file:** this is an
unlisted route with **no client-side gating**. It renders, calls the API, and shows an access-denied
state when the server returns 403. The page deliberately does **not** read `user.roles` to decide
whether to render — authorization is never inferred client-side (RBAC-02), and a client-side guard
here would be security theatre that also drifts from the server's real answer.

**On mount:** `GET /api/admin/authority-claims`.
- 401 → `נדרשת התחברות`
- 403 → `אין לכם הרשאה לצפות במסך הזה.` and nothing else — no queue shape, no counts, no hints
- 200 → the queue

**Each queue row** renders everything a reviewer needs to decide without leaving the page:
- the organization's `legalName` and `displayNameHe`, and the municipality
- the claimant's name, email, and `claimedRoleHe`
- the `motivation` text in full
- the `evidenceUrls` as a numbered list of external links, each `target="_blank"`
  `rel="noopener noreferrer"`, with the raw href visible as text so a reviewer can see where a link
  goes before clicking it
- the submission timestamp in `he-IL`, `Asia/Jerusalem` (match the `Intl.DateTimeFormat` config
  already used in `municipality/[slug]/page.tsx`)

**Decision controls:** a required reason textarea (minimum 10 characters, matching
`ReviewReasonSchema`) and two buttons, `אישור ואימות` and `דחייה`. Both disabled until the reason is
long enough — and the disabled state must be visually obvious, not just non-functional. Label the
reason field `נימוק ההחלטה (נשמר לצמיתות)` so the reviewer knows it is part of a permanent record.

Before the approve action fires, an inline confirmation restating what approval does:
`אישור יהפוך את הגוף לרשות הרשמית של {municipality}, ייתן למגיש הרשאת ניהול לרשות הזו, וירשם ביומן הביקורת עם שמכם והנימוק.`
Approval is the one irreversible-feeling action in this phase; the reviewer should read that sentence
once.

**After a decision:** POST `/api/admin/authority-claims/[id]`, remove the row from the queue, and show
the outcome inline. Map 409 → `הבקשה כבר טופלה על ידי מנהל אחר.` and 409
`municipality_already_verified` → `לרשות הזו כבר יש גוף מאומת אחר.`

Include a link to `/[locale]/admin/manager-applications` and back, so the two consoles are one
operator surface rather than two unlisted URLs nobody can find.

CSS module: tokens only; reuse the Phase 5 console's class vocabulary where it applies.
