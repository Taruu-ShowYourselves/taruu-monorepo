**Section 1 — `official_responses` (AUTH-04).**

```sql
-- Append-only version chain. A revision is a NEW ROW with version = previous + 1;
-- the prior row's body, byline and timestamp are never touched. Retraction is a new
-- version with publication_state = 'retracted', not an UPDATE and not a DELETE.
CREATE TABLE official_responses (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  vote_id UUID NOT NULL REFERENCES votes(id) ON DELETE CASCADE,
  organization_id UUID NOT NULL REFERENCES authority_organizations(id) ON DELETE RESTRICT,
  municipality_id TEXT NOT NULL REFERENCES municipalities(code),

  version INTEGER NOT NULL CHECK (version >= 1),
  body_he TEXT NOT NULL CHECK (char_length(body_he) BETWEEN 20 AND 5000),
  publication_state TEXT NOT NULL DEFAULT 'published'
    CHECK (publication_state IN ('published','retracted')),
  revision_note TEXT,

  -- AUTH-05: the byline must survive the author being offboarded or their user row
  -- being deleted. The FK goes NULL; the snapshot does not.
  author_user_id UUID REFERENCES users(id) ON DELETE SET NULL,
  author_display_name TEXT NOT NULL,
  author_org_name_he TEXT NOT NULL,

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
  -- No updated_at, by design. Nothing here is ever updated.
);

CREATE UNIQUE INDEX uq_official_responses_version
  ON official_responses (vote_id, organization_id, version);
CREATE INDEX idx_official_responses_vote
  ON official_responses (vote_id, version DESC);

CREATE TRIGGER official_responses_append_only
  BEFORE UPDATE OR DELETE ON official_responses
  FOR EACH ROW EXECUTE FUNCTION public.reject_audit_mutation();
```

`ON DELETE RESTRICT` on `organization_id` is deliberate and must be commented: an organization with
published responses cannot be deleted out from under the public record — it can only be suspended.

**Section 2 — `authority_commitments` (AUTH-05, AUTH-06).** Same append-only shape, keyed by a
stable `thread_id` so versions of one target group together:

```sql
CREATE TABLE authority_commitments (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  thread_id UUID NOT NULL,
  organization_id UUID NOT NULL REFERENCES authority_organizations(id) ON DELETE RESTRICT,
  municipality_id TEXT NOT NULL REFERENCES municipalities(code),
  vote_id UUID REFERENCES votes(id) ON DELETE SET NULL,

  version INTEGER NOT NULL CHECK (version >= 1),
  title_he TEXT NOT NULL CHECK (char_length(title_he) BETWEEN 3 AND 200),
  detail_he TEXT CHECK (detail_he IS NULL OR char_length(detail_he) <= 4000),

  -- AUTH-06: tracking states, NOT legal states. No column here is named deadline,
  -- due, obligation, sla or breach, and none ever will be.
  workflow_state TEXT NOT NULL CHECK (
    workflow_state IN ('draft','published','in_progress','done','stalled','escalated','withdrawn')
  ),
  target_date DATE,
  transition_note TEXT,

  author_user_id UUID REFERENCES users(id) ON DELETE SET NULL,
  author_display_name TEXT NOT NULL,

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX uq_authority_commitments_version
  ON authority_commitments (thread_id, version);
CREATE INDEX idx_authority_commitments_org
  ON authority_commitments (organization_id, thread_id, version DESC);

CREATE TRIGGER authority_commitments_append_only
  BEFORE UPDATE OR DELETE ON authority_commitments
  FOR EACH ROW EXECUTE FUNCTION public.reject_audit_mutation();
```

`COMMENT ON TABLE authority_commitments`: "Append-only version chain of authority tracking targets
(AUTH-05, AUTH-06). workflow_state and target_date are public tracking information only. They carry
NO legal claim, create no obligation and are not enforceable; the UI states this in Hebrew on every
page that renders them."

`COMMENT ON COLUMN authority_commitments.target_date`: "A tracking date the authority published for
itself. Deliberately not named 'deadline' or 'due_date'."

**Section 3 — `authority_satisfaction_snapshots` (AUTH-03, AUTH-05).**

```sql
CREATE TABLE authority_satisfaction_snapshots (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  municipality_id TEXT NOT NULL REFERENCES municipalities(code),
  snapshot_date DATE NOT NULL,
  cohort_size INTEGER NOT NULL CHECK (cohort_size >= 0),
  -- NULL whenever withheld: a suppressed aggregate stores no approximation.
  satisfaction_avg NUMERIC(4,2),
  withheld BOOLEAN NOT NULL DEFAULT FALSE,
  -- The floor in force when this row was captured, so a historical figure can be
  -- read back against the rule that produced it.
  min_cohort_size INTEGER NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  CONSTRAINT satisfaction_withheld_has_no_value_ck CHECK (
    (withheld = TRUE AND satisfaction_avg IS NULL) OR withheld = FALSE
  )
);

CREATE UNIQUE INDEX uq_satisfaction_snapshot_day
  ON authority_satisfaction_snapshots (municipality_id, snapshot_date);

CREATE TRIGGER authority_satisfaction_snapshots_append_only
  BEFORE UPDATE OR DELETE ON authority_satisfaction_snapshots
  FOR EACH ROW EXECUTE FUNCTION public.reject_audit_mutation();
```

Comment: no author FK at all — a satisfaction history must survive every staff change without even
a nullable reference to a person (AUTH-05). Written idempotently on dashboard read, at most once
per municipality per UTC day; there is no cron for this (08-CONTEXT decision 8 — this account's
Cloudflare cron list is gated).

`satisfaction_withheld_has_no_value_ck` makes AUTH-03's "withheld, not rounded" rule a database
constraint, not a code convention.

**Section 4 — current-version views.** Both with `security_invoker = on` so the caller's RLS
applies rather than the view owner's (Supabase is PG15+; a view without this silently runs as a
definer and would bypass the policies below):

```sql
CREATE VIEW official_responses_current
  WITH (security_invoker = on) AS
  SELECT DISTINCT ON (vote_id, organization_id) *
  FROM official_responses
  ORDER BY vote_id, organization_id, version DESC;

CREATE VIEW authority_commitments_current
  WITH (security_invoker = on) AS
  SELECT DISTINCT ON (thread_id) *
  FROM authority_commitments
  ORDER BY thread_id, version DESC;
```

**Section 5 — RLS.**

`official_responses` is **deliberately world-readable**, and the reason must be written into the
migration because Phase 7's MIG-01 requires every `USING (true)` policy to carry one:

```sql
ALTER TABLE official_responses ENABLE ROW LEVEL SECURITY;
-- DELIBERATELY PUBLIC (MIG-01 justification): an official response is a public
-- statement by a public authority. Its revision history is public by design —
-- suppressing prior versions would defeat the point of versioning them, and
-- residents' ability to see what changed is exactly what makes the record
-- trustworthy. Read-only; the service-role repo is the only write path.
CREATE POLICY "official_responses_select_public"
  ON official_responses FOR SELECT TO anon, authenticated USING (true);
```

`authority_commitments` and `authority_satisfaction_snapshots` are authority-scoped until the
authority publishes; keep them behind the scope helper (public surfacing of targets is not a
criterion of this phase and is easy to add later, whereas leaking a draft is not easy to undo):

```sql
CREATE POLICY "authority_commitments_select_member"
  ON authority_commitments FOR SELECT TO authenticated
  USING ((SELECT public.is_authority_member(municipality_id)));
CREATE POLICY "authority_commitments_select_admin"
  ON authority_commitments FOR SELECT TO authenticated
  USING ((SELECT public.is_platform_admin()));
CREATE POLICY "satisfaction_snapshots_select_member"

CREATE POLICY "satisfaction_snapshots_select_admin"
  ON authority_satisfaction_snapshots FOR SELECT TO authenticated
  USING ((SELECT public.is_platform_admin()));
```
