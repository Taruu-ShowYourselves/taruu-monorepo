Create the access half of Phase 8's schema — organizations, claims and representative invitations —
by **extending** Phase 5's role and audit tables rather than duplicating them, and publish the
shared contracts every later plan parses against.

Purpose: success criterion 1 ("an unreviewed organization gets no badge, no dashboard, no
official-response authorship") and criterion 2 ("cross-municipality isolation") are both far
stronger as schema constraints than as code paths. This plan makes "verified without evidence"
and "two official municipalities" unrepresentable in the database.

**Section 2 — `authority_organizations`.**

```sql
CREATE TABLE authority_organizations (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  municipality_id TEXT NOT NULL REFERENCES municipalities(code),
  legal_name TEXT NOT NULL CHECK (char_length(legal_name) BETWEEN 2 AND 200),
  display_name_he TEXT NOT NULL CHECK (char_length(display_name_he) BETWEEN 2 AND 120),
  contact_email TEXT NOT NULL,
  contact_phone TEXT,
  website_url TEXT,

  verification_status TEXT NOT NULL DEFAULT 'unverified'
    CHECK (verification_status IN ('unverified','verified','suspended','rejected')),
  verified_by UUID REFERENCES users(id) ON DELETE SET NULL,
  -- Byline snapshot: the reviewer's identity must survive their user row being deleted.
  verified_by_name TEXT,
  verified_at TIMESTAMPTZ,
  verification_reason TEXT,
  -- Copied off the approved claim so the evidence outlives the claim row.
  verification_evidence JSONB NOT NULL DEFAULT '[]'::jsonb,

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  -- AUTH-01, in the schema: verification is never automatic and never undocumented.
  -- A verified row without an actor, a timestamp and a reason is not representable.
  CONSTRAINT authority_org_verified_evidence_ck CHECK (
    verification_status <> 'verified'
    OR (verified_by IS NOT NULL AND verified_at IS NOT NULL AND verification_reason IS NOT NULL)
  )
);

-- AUTH-01: at most one official municipality. Partial, so a rejected or suspended
-- organization can be re-reviewed later without the index blocking it forever.
CREATE UNIQUE INDEX uq_authority_org_verified
  ON authority_organizations (municipality_id)
  WHERE verification_status = 'verified';

CREATE INDEX idx_authority_org_municipality
  ON authority_organizations (municipality_id, verification_status);

CREATE TRIGGER update_authority_organizations_updated_at
  BEFORE UPDATE ON authority_organizations
  FOR EACH ROW EXECUTE FUNCTION update_updated_at_column();
```

`COMMENT ON TABLE`: "The municipal body claiming a municipality (AUTH-01). Verification is a
super-admin decision with recorded evidence, actor, timestamp and reason — enforced by
authority_org_verified_evidence_ck, never by application code alone."

**Section 5 — the scope helper.** Mirror `can_admin_space` exactly, including the
anti-recursion note:

```sql
CREATE OR REPLACE FUNCTION public.is_authority_member(p_space TEXT)
RETURNS BOOLEAN
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT p_space IS NOT NULL AND EXISTS (
    SELECT 1 FROM public.role_grants g
    WHERE g.user_id = public.user_id()
      AND g.role IN ('authority_admin','authority_rep')
      AND g.space_id = p_space
      AND g.status = 'active'
  );
$$;
```

`COMMENT ON FUNCTION`: "True when the JWT subject holds an active authority grant for p_space.
SECURITY DEFINER with a pinned search_path for the same anti-recursion reason as
is_platform_admin() — a policy that queries role_grants without it raises 42P17. This is not a
style choice."
