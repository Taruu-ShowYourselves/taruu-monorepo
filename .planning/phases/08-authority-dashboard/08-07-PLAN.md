> AUTH-03. Two rules govern every value that leaves this module.
>
> 1. **Scope.** The municipality comes from `resolveAuthorityScope(userId)` and from nowhere else.
>    Neither function here takes a municipality parameter, so there is no place for a request value
>    to enter. Plan 08-13 greps this directory for one.
> 2. **The floor.** Every aggregate this phase INTRODUCES passes through `applyCohortFloor` before
>    it is serialized. Figures that are already public on the council page (open/closed vote counts,
>    participant totals) are carried verbatim and deliberately NOT floored — flooring an
>    already-public number would hide from the authority what an anonymous visitor can already see.
>    That asymmetry is intentional; see 08-CONTEXT decision 5.

`getAuthorityDashboard(userId)`:
1. `resolveAuthorityScope(userId)`.
2. Call the existing `municipality_profile_metrics` RPC through `supabaseAdmin.rpc(...)` from a
   small private helper in this file (**not** by importing `getMunicipalityProfile`, and **not** by
   adding a function to `db.ts` — the public path stays untouched).
3. Public totals: counts of open and closed votes and the participant total, straight through.
4. `satisfaction = applyCohortFloor(satisfaction_avg, satisfaction_count)`.
5. `participationRate = applyCohortFloor(participants / residents, participants)` and
   `medianTimeToParticipateHours = applyCohortFloor(avg_time_hours, participants)` — floored on the
   participant cohort, not the resident count, because the participants are the people the figure
   describes.
6. `responseCoverage` from `findCurrentResponses(ctx.organizationId, voteIds)`: counts only, no
   floor (a count of the authority's own published documents identifies no resident).
7. Snapshot, best-effort and idempotent: build the row from step 4 —
   `{ municipality_id, snapshot_date: <UTC today>, cohort_size: satisfaction_count,
   satisfaction_avg: <null when withheld>, withheld, min_cohort_size: MIN_COHORT_SIZE }` — and call
   `upsertSatisfactionSnapshot`. **A snapshot failure must never fail the dashboard**: recover the
   Result and log at warn. Comment that this is the only write on a GET and why there is no cron
   (08-CONTEXT decision 8).
8. `satisfactionHistory` from `listSatisfactionSnapshots(ctx.municipalityId, 90)`.

`getVoteInbox(userId)`:
1. `resolveAuthorityScope(userId)`.
2. Votes for `ctx.municipalityId` — `id, title, status, start_date, end_date, participant_count`
   plus `vote_options(text, votes)` for the winning option, ordered `end_date DESC`, limit 200.
   **Never** select from `user_votes` and never join `users`. Say so in a comment: the inbox is
   about votes, and a per-resident row here is exactly the "resident identity access" the issue puts
   out of scope.
3. Merge `findCurrentResponses` and `listCurrentCommitments` to fill `officialResponse` and
   `hasCommitment`.

Neither function accepts a municipality argument. If a future caller needs one, it goes through

**A. `apps/web/src/server/app/authority/export.ts`.**

```ts
export type AuthorityDataset = 'votes' | 'responses' | 'commitments';

/** Minimal, dependency-free CSV writer: RFC4180 quoting, UTF-8 BOM for Excel + Hebrew. */
export function toCsv(headers: string[], rows: (string | number | null)[][]): string;

export function exportAuthorityDataset(
  userId: string,
  dataset: AuthorityDataset
): ResultAsync<{ filename: string; csv: string }, AppError>;
```

Header comment: an export is the highest-risk read surface in this phase, because a CSV leaves the
product and stops being governed by the UI. Three rules, all asserted by tests:
1. Scope from `resolveAuthorityScope` only.
2. **No resident identifier in any column, ever** — not `user_id`, not email, not phone, not DID,
   not a name. The column allow-list is written literally in this file, and the test asserts the
   generated header row is exactly that list.
3. Every introduced aggregate column carries the floor: a withheld cell renders as the literal
   Hebrew string `לא מוצג` (withheld), never as a blank, a zero or an approximation. A blank is
   indistinguishable from missing data; `לא מוצג` says a decision was made.

Datasets:
- `votes` — `voteId, title, status, startDate, endDate, participantCount, winningOption,
  hasOfficialResponse` (from `getVoteInbox`)
- `responses` — `voteId, version, publicationState, authorDisplayName, authorOrgNameHe, createdAt,
  revisionNote` — the **full version history**, because an export whose point is accountability that
  showed only the latest text would be worse than none
- `commitments` — `threadId, version, titleHe, workflowState, targetDate, authorDisplayName,
  createdAt, transitionNote`

Prefix the CSV with `﻿` so Excel renders Hebrew correctly, and comment why.
