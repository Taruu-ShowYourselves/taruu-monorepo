# Agent task PRD template

## Problem

Who is affected, what is failing or missing, and why this matters now.

## Outcome

The observable user or operational outcome. Include the primary user story.

## Context

Relevant product decisions, existing behavior, code paths, linked issues,
design references, data constraints, and external-service constraints.

## Scope

### In scope

- Exact behavior to add or change.

### Out of scope

- Explicit exclusions that prevent accidental scope expansion.

## Requirements

- Functional requirements.
- UX and RTL/Hebrew requirements where relevant.
- Data/API/security/compatibility requirements.
- Failure, empty, loading, and recovery behavior.

## Acceptance criteria

- [ ] Each item is independently verifiable.
- [ ] Include regression expectations.

## Verification plan

- Automated commands to run.
- Manual flows and test data.
- Expected results and important negative cases.

## Visual evidence

List the exact routes/screens, viewport(s), locale, authentication state, and
UI states to capture. If the change is not visual, write:

`Visual evidence: Not applicable — <specific reason>.`

## Risks and rollback

Security/privacy concerns, migration and deployment risks, feature flags or
rollback steps, and any monitoring required after release.
